# CLAUDE.md

Правила работы агента лежат в [AGENTS.md](AGENTS.md). Прочитай его перед любым модулем. План модулей (M0-M19): [PLAN.md](PLAN.md). Исходное задание: [TZ-YouTube.md](TZ-YouTube.md).

## Цель проекта

Копия YouTube на уровне тестового задания: регистрация, загрузка и обработка видео, просмотр с перемоткой, лайки, комментарии, подписки, каналы, плейлисты, поиск, модерация, роли. Деплой на чистую Ubuntu одной командой. Язык интерфейса, README и docs: русский. Код и имена: английский.

## Стек

- Backend: Python 3.12, FastAPI (эндпоинты `def`, синхронный стек), SQLAlchemy 2.x sync + psycopg 3, Alembic, Pydantic v2.
- БД: PostgreSQL 16, расширения `citext`, `pg_trgm`.
- Хранилище: MinIO (S3 API через `boto3`), бакеты приватные.
- Очередь: таблица `jobs` в PostgreSQL (`FOR UPDATE SKIP LOCKED`), контейнер `worker`, `ffmpeg`.
- Frontend: HTML/CSS/JS без сборки и без внешних CDN, нативный `<video controls>`.
- Инфраструктура: nginx, Docker Compose, `scripts/deploy.sh`.
- Качество: `ruff` (lint + format, правила `S`), `pytest`, `bandit`, `pip-audit`.

## Структура каталогов

```
backend/app/{core,models,schemas,api/v1,services,storage,worker}   backend/alembic   backend/tests
frontend/ (*.html, css/, js/)    infra/ (docker-compose.yml, nginx.conf)    scripts/ (deploy.sh, seed.py, smoke.sh)
docs/ (+ adr/)    prompts/    .claude/ (agents, commands, skills, settings.json)
```

Слои backend: router → service (бизнес-логика и запросы к БД) → модели. Слоя репозиториев нет. Полная схема: раздел 2 в `PLAN.md`.

## Команды

Из корня проекта. Цели помечены модулем, в котором они появляются.

| Что | Команда | Модуль |
| --- | --- | --- |
| Линтер (lint + проверка формата) | `make lint` | M0 |
| Автоформат и автоисправление | `make format` | M0 |
| Тесты | `make test` (`python -m pytest`) | M0 |
| Запуск и остановка стека | `make up`, `make down`, `make logs` | M2 |
| Миграции | `make migrate` (`alembic upgrade head`) | M2/M3 |
| Демо-данные | `make seed` | M16 |
| Деплой на Ubuntu | `sudo ./scripts/deploy.sh` | M17 |
| Проверка после деплоя | `scripts/smoke.sh` | M17 |

Если нужной цели ещё нет в `Makefile`, добавь её в том модуле, где она запланирована, и не придумывай другие имена.

## Соглашения по коду

- Каждая новая ручка сразу получает: схему Pydantic (без лишних полей), описание и коды ответов в Swagger, проверку прав, тест.
- Права на видео проверяет одна функция `can_view(user, video)`, она вызывается во всех ручках, отдающих метаданные, поток, превью, комментарии, реакции.
- Только параметризованные запросы. Ключи S3 генерирует сервер, имя файла пользователя в ключ не попадает.
- Пользовательские данные на фронте выводятся только через `textContent` и атрибуты, `innerHTML` с ними запрещён.
- Секреты не хранятся в коде и логах. В репозитории только `.env.example`. Файл `.env` не читать и не править.
- Никаких внешних сервисов в рантайме (CDN, шрифты, внешние API).
- Новые зависимости: только с зафиксированной версией.
- Стиль: `ruff`, длина строки 100, двойные кавычки. Комментарии только там, где неочевидно «почему».
- Решения с альтернативами фиксируются в `docs/adr/NNN-название.md` (контекст → варианты → решение → последствия).

## Правила для агента

1. **Агент не использует git.** Никаких команд `git` и `gh`, включая чтение истории. Коммиты ведёт пользователь. В `.claude/settings.json` это запрещено технически.
2. **Сначала тест на критичное поведение** (права доступа, аутентификация, счётчики, загрузка и обработка), затем реализация.
3. **После изменений прогоняй `make test` и `make lint`.** Пока они не зелёные, модуль не закрыт. Если цель ещё не существует, скажи об этом в отчёте.
4. **Не выходить за рамки раздела 0.3 из `AGENTS.md`** (рекомендации, HLS, свой плеер, уведомления и т.д.). Если задача выходит за рамки раздела 0.2, остановись и спроси пользователя.
5. **Не удалять файлы без спроса.**
6. **Один модуль за раз.** К следующему переходи только после критериев готовности модуля и общего DoD из `PLAN.md`.
7. Ключевые промпты модуля сохраняй в `prompts/` (формат в `prompts/README.md`).

## Формат отчёта по модулю

В конце каждого модуля, на русском:

1. **Что сделано:** кратко, по задачам модуля.
2. **Изменённые файлы:** список путей (создано / изменено). По нему работает `/review`.
3. **Как проверить:** точные команды или шаги в Swagger и браузере.
4. **Результаты тестов:** вывод `make test` и `make lint` (число тестов, падения), что не удалось запустить и почему.
5. **Критерии готовности и DoD:** чек-лист с отметками, невыполненные пункты названы явно.
6. **Допущения и открытые вопросы.**
7. Опционально одна строка с предложением текста коммита. Сам коммит не делается.
