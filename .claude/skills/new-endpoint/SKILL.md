# new-endpoint

Добавляй ручку строго в таком порядке. Эндпоинты синхронные (`def`).

## 1. Тест (сначала)

`backend/tests/api/test_<area>.py`. Минимум:
- успешный сценарий;
- гость без токена: 401, если нужна аутентификация;
- чужой пользователь или недостаточная роль: 403 (или 404, если существование объекта нельзя раскрывать);
- невалидные данные: 422;
- ошибка предметной области (дубликат, конфликт статуса): 409 и т.п.

Если ручка отдаёт или меняет данные видео, добавь строки в матрицу доступа (гость / чужой / владелец / получивший доступ / модератор).

## 2. Схемы Pydantic

`backend/app/schemas/<area>.py`. Отдельные модели для входа (`XxxCreate`, `XxxUpdate`) и выхода (`XxxOut`). Только нужные поля: пароли, хэши, внутренние ключи S3 в ответ не попадают, роль и `is_hidden` из тела запроса не принимаются. Ограничения через `Field` (длины, диапазоны). `model_config = ConfigDict(from_attributes=True)` для выходных моделей.

## 3. Сервис

`backend/app/services/<area>.py`. Бизнес-логика и запросы к БД: параметризованный SQLAlchemy 2.x, без сырых строк с интерполяцией. Функции принимают `Session` и доменные объекты, не `Request`. Счётчики меняются атомарно (`UPDATE ... SET n = n + 1`) в той же транзакции. Доступ к видео проверяется через `can_view(user, video)`. Исключения предметной области уходят в единый формат ошибок.

## 4. Роутер

`backend/app/api/v1/<area>.py`:

```python
@router.post(
    "/{video_id}/example",
    response_model=ExampleOut,
    status_code=status.HTTP_201_CREATED,
    summary="Короткое описание на русском",
    responses={401: {...}, 403: {...}, 404: {...}, 409: {...}},
)
def create_example(
    video_id: UUID,
    payload: ExampleCreate,
    db: Session = Depends(get_db),
    user: User = Depends(get_current_user),  # get_optional_user, если ручка публичная
) -> ExampleOut:
    return example_service.create(db, user, video_id, payload)
```

Права: `get_current_user`, `get_optional_user` или `require_role(...)`. Проверка владельца или `can_view` внутри сервиса, не только в роутере. Подключи роутер в `app/api/v1/__init__.py`. Для ручек входа, регистрации, комментариев, реакций, жалоб и загрузки добавь rate limit.

## 5. Документация и проверка

- Теги, `summary`, описание и коды ответов видны в `/docs`.
- Обнови `docs/` модуля (например, `docs/security.md`, если изменилась матрица прав).
- Прогони `make test` и `make lint`.
- В отчёте перечисли новые файлы и как вызвать ручку через Swagger или `curl`.

Не используй `git`. Не выходи за рамки раздела 0.3 из `AGENTS.md`.
